# Что сделано в неделях 3–7

Работа сохранена локально в ветке `coursework-weeks-3-7`. Перед публикацией можно открыть каждую неделю и проверить её отдельно. Для недель 3–5 использованы прежние локальные наработки, затем внесены исправления по присланным заданиям. Недели 6–7 добавлены на их основе.

## Как меняется проект

| Неделя | Что добавлено | С чего начать чтение |
|---|---|---|
| 3 | Загрузка проектов и сроков из JSON, проверка данных, сообщения загрузки и ошибок, погода | `src/api.ts`, `src/guards.ts`, `src/main.ts` |
| 4 | Страница разбита на React-компоненты, данные передаются через props | `src/main.tsx`, `src/App.tsx`, `src/components/ProjectCard.tsx` |
| 5 | Форма хранит введённый текст в состоянии, проверяет поля и сохраняет проекты | `src/validation.ts`, `src/components/AddProjectForm.tsx`, `src/hooks/useLocalStorage.ts` |
| 6 | Отдельные страницы Dashboard, Projects, Deadlines, детали проекта и 404 | `src/App.tsx`, `src/components/Layout.tsx`, `src/pages/ProjectDetailsPage.tsx` |
| 7 | React сам загружает данные и отменяет ненужные запросы | `src/hooks/useFetch.ts`, `src/App.tsx`, `src/components/WeatherCard.tsx` |

В третьей неделе `fetch` получает данные. Guard проверяет их форму. После этого страница показывает список или ошибку. В четвёртой неделе ту же страницу собирают компоненты React.

В пятой неделе состояние хранит значения формы и добавленные проекты. `localStorage` сохраняет проекты после обновления страницы. В шестой неделе адрес определяет, какую страницу показать. В седьмой `useFetch` управляет запросом, результатом и отменой.

Использованы небольшие функции, обычные условия, `map` и `filter`. Обобщённые типы `LoadState<T>`, `useLocalStorage<T>` и `useFetch<T>` оставлены, потому что они прямо требуются заданиями.

## Как запустить

Открой терминал в нужной папке, например `week07-react-data`, и выполни команды.

```bash
npm ci
npm run dev
```

Открой адрес, который напишет Vite. Для проверки сборки выполни `npm run build`. В неделях 4–7 также есть `npm run lint`.

В шестой и седьмой неделях можно открыть `/projects`, `/deadlines`, `/projects/p1` и `/missing`.

## Ошибки для разбора

Следующие ошибки были специально внесены на время эксперимента и затем исправлены.

### Поле не принимает текст

В пятой неделе у поля временно убран `onChange`, но оставлен `value`. При попытке написать `hello` поле осталось пустым, а React показал предупреждение. Исправление — вернуть `onChange`, который обновляет состояние.

```tsx
value={values.title}
onChange={(event) => update("title", event.target.value)}
```

### Изменение старого объекта

Временный вариант `values.description = ...; setValues(values)` не обновлял поле. После ввода в другом поле появился последний символ. Исправление — передавать новый объект через `setValues((current) => ({ ...current, [name]: value }))`.

### Слишком много запросов

В седьмой неделе временно убран массив зависимостей эффекта. За короткую проверку возникло 92 запроса вместо нескольких. Также проверена функция, созданная прямо внутри `App` — получилось 46 запросов. Итоговый вариант использует `[fetcher, attempt]` и функции из `api.ts`.

### Ошибки props

В четвёртой неделе временно убран обязательный `note`, затем указан `tone="green"`. TypeScript показал TS2741 и TS2322. При удалении `key` типы прошли проверку, но lint нашёл ошибку.

Во время общей проверки также найдены и исправлены две обычные ошибки реализации. Длинное слово растягивало карточку на телефоне. Заблокированный `localStorage` мог прерывать третью неделю. Обе ситуации повторно проверены после исправления.

В шестой неделе сохранён предусмотренный заданием недостаток — позиция прокрутки может оставаться после перехода. Седьмая неделя добавляет исправление.
